## 3. Как обновлять DESIGN.md при добавлении новых компонентов

Когда добавляешь новый CSS-класс или компонент:

1. **Сначала — `styles.css`:** добавь класс в конец файла, в секцию
   соответствующего компонента, с подробным комментарием «зачем».
2. **Потом — `DESIGN.md` §3:** добавь запись в раздел компонента:
   - назначение в одну строку,
   - таблица классов,
   - HTML-скелет,
   - 1-2 пункта do/don't.
3. **Если новый токен** — добавь в `DESIGN.md §2` (цвета/тени/радиусы/отступы).
4. **Если есть смысл** — добавь рецепт в `SKILLS.md` (раздел 15 — напоминание).
5. **Закоммить** — в одном коммите с кодом (или отдельно — на твоё усмотрение).

**Пример:** добавил `.alert` для системных сообщений. Обнови:
- `styles.css` → секция `/* === Alerts === */` (новая).
- `DESIGN.md §3` → пункт 3.X «Alerts» с HTML-скелетом.
- `DESIGN.md §5` → убрать `.alert` из списка «отсутствует».
- `SKILLS.md` → рецепт «Показать системное сообщение» (если нужно часто).

## 4. Как добавить новый «навык» в SKILLS.md

Если ты делаешь однотипную задачу 3+ раз — вынеси в рецепт:

1. Открой `SKILLS.md`, найди подходящий раздел или создай новый.
2. Структура рецепта: **короткое описание → файлы → код с реальными импортами**.
3. Не больше 50 строк кода на рецепт — иначе это уже не рецепт, а туториал.
4. Все импорты — из реальных файлов проекта (не выдуманные).
5. Не дублируй то, что уже есть. Лучше отрефакторить — один источник правды.

## 5. План развития дизайн-системы

Это список того, что **стоит добавить в будущем**, но пока отсутствует.
Не пытайся имитировать хардкодом — добавь класс, обнови DESIGN.md.

### 5.1. Компоненты

| Что                  | Зачем                                              | Сложность |
|----------------------|----------------------------------------------------|-----------|
| `.alert` / `.banner` | Системные сообщения поверх контента (не toast)    | Низкая    |
| `.tooltip`           | Подсказки по наведению (сейчас `title=`)           | Средняя   |
| `.tabs`              | Горизонтальные табы (нет общего — есть частные)    | Низкая    |
| `.pagination`        | Постраничная навигация (сейчас `limit=500`)        | Низкая    |
| `.spinner`           | Визуальная загрузка (сейчас текст «Загрузка…»)     | Низкая    |
| `.switch`            | on/off переключатель (есть `toggle-group`, но radio)| Низкая   |
| `.breadcrumb`        | Навигационная цепочка                              | Средняя   |
| `.avatar`            | Круглый аватар (пользователь/контрагент)          | Низкая    |

### 5.2. Технический долг

| Что                                                   | Зачем                                                    |
|-------------------------------------------------------|----------------------------------------------------------|
| Хардкод `#f0f2f7` в `.table th`                       | Вынести в токен `--surface-muted` (для тёмной темы)      |
| Хардкод `#f0f2f7` / `rgba(0,0,0,0.02)` в hover/итогах | Часть — норма, но при тёмной теме сломается              |
| Inline-стили в `transactions.js` (комментарий-edit)    | Переписать через `.comment-cell.editing input {…}`       |
| Inline-стили в `accounts.js:69, 78` (итоговая строка) | Переписать через `.table tfoot td` или отдельный класс   |
| `#1a8754` для `profit-pos`                            | Решить: перевести на `--success` или оставить (намеренный контраст с зелёным «доход») |

### 5.3. Рефакторинг (большие задачи — НЕ делать без отдельного запроса)

#### 5.3.1. `innerHTML` → `createElement`

Текущий код (`transactions.js`, `accounts.js`, `dashboard.js`, `simple-list.js`)
использует шаблонные строки + `innerHTML`. Это:
- **допустимо** для статической разметки при условии `escapeHtml()` на каждом
  пользовательском значении (так и сделано сейчас),
- **опасно**, если кто-то добавит пользовательский ввод без escape.

**План:** постепенно переписать вьюхи в стиле (2) — `createElement`. Начать с
простых (одна таблица, без фильтров). Не делать одной большой миграцией —
- риск сломать много страниц разом.

#### 5.3.2. Тёмная тема

Все токены уже централизованы — добавить тёмную тему относительно просто:

1. Создать `:root[data-theme="dark"]` с переопределением `--bg`, `--surface`,
   `--text`, `--muted`, `--border`. (Хардкод `#f0f2f7` в `.table th` —
   вынести в токен `--surface-muted`.)
2. Тоггл темы в `.topbar-meta`.
3. Сохранять выбор в `localStorage.theme`.
4. Проверить все компоненты (см. §5.1) на контраст.

#### 5.3.3. Сборка

Сейчас всё грузится as-is. Если проект разрастётся (> 30 вьюх):
- ESBuild для бандла JS.
- Один файл `styles.css` → можно разделить по компонентам + сборка (НЕ делать
  без явного запроса — это сломает текущий workflow).

## 6. Частые ошибки агентов (запомни сам)

Когда агенты берутся за задачу, они часто:

1. **Пытаются добавить npm-пакет.** Прямо в первой строке `package.json`.
   → Дай ссылку на AGENTS.md §3.
2. **Изобретают новый CSS-файл.** `styles.module.css`, `tailwind.config.js`.
   → Дай ссылку на DESIGN.md §1 «принципы».
3. **Хардкодят цвета.** `style="color: #2563eb"` вместо `var(--accent)`.
   → Дай ссылку на DESIGN.md §2.1.
4. **Используют `confirm()` для неразрушительных действий.**
   → Для подтверждения типа «Точно хотите X?» — toast, не confirm.
5. **Забывают `escapeHtml()`.** Особенно в новых вьюхах «по образцу transactions».
   → В ревью ВСЕГДА проверяй `innerHTML` блоки.
6. **Создают свой `openModal` внутри вьюхи.** Вместо того чтобы пользоваться `ui/modal.js`.
   → Дай ссылку на SKILLS.md §3.
7. **Регистрируют маршрут, но не добавляют в `titleMap`.** В топбаре — «Finans» вместо названия.
   → В чеклисте (AGENTS.md §6) это уже есть.

## 7. Как обновить этот набор файлов

Если меняешь стек (например, добавляешь новую вьюху-папку или сборку):

1. **AGENTS.md §1 «Стек»** — обнови список путей.
2. **AGENTS.md §2 «Архитектура»** — если меняется жизненный цикл.
3. **CLAUDE.md** — краткая выжимка стека (5 строк).
4. **`.cursor/rules/design-system.mdc`** — globs (если новые папки).
5. **README-AI.md** — этот файл, раздел «Что за что отвечает».

Не забывай — **контракт должен быть консистентным**. Если в одном файле
сказано «vanilla JS», а в другом — «React» — агенты запутаются.

## 8. TL;DR для очень нетерпеливых

1. Перед каждой задачей копируй шаблон промпта из §2.
2. DESIGN.md — токены и компоненты (главный файл).
3. SKILLS.md — копируй рецепты.
4. AGENTS.md — когда сомневаешься «можно ли?».
5. После добавления компонента — обнови DESIGN.md §3.
